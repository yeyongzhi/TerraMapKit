# 安装与使用

## 仓库开发

需要 Node.js 22 或以上和 pnpm 10.4.1，在仓库根目录运行：

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm example:dev
```

示例地址为 `http://127.0.0.1:5173`。`pnpm docs:dev` 启动说明文档站。修改库源码后重新构建或重启 `example:dev`。

## 本地包安装

当前未发布 npm 包，不能假定 `pnpm add terra-map-kit` 可安装本项目。先在仓库生成本地包：

```bash
pnpm package:check
```

然后在消费项目安装 `cesium` 与该 tgz 的绝对路径。公开发布后的包名和版本需以正式发布信息为准。

### Cesium 1.145.0 的依赖组合

本次独立安装发现：Cesium 1.145.0 的浮动子依赖可能解析到 engine 26.4.0/widgets 16.3.0，导致入口缺少 AttributeCompression 导出。本仓库锁文件中的 engine 26.3.0/widgets 16.2.0 正常。要复现本次验证环境，消费项目将 cesium 固定为 1.145.0，并在根 package.json 配置：

```json
{
  "pnpm": {
    "overrides": {
      "@cesium/engine": "26.3.0",
      "@cesium/widgets": "16.2.0"
    }
  }
}
```

这是本次实际安装发现的上游版本组合问题，不代表后续版本都需沿用此设置。选择其他 Cesium 版本时需重新验证；工具库不把 overrides 强制传递给消费应用。

## Cesium 资源配置

应用负责将安装的 `cesium/Build/Cesium` 下 Workers、ThirdParty、Assets、Widgets 复制到自己的静态资源目录，设置 `CESIUM_BASE_URL` 指向该目录，并导入 `cesium/Build/Cesium/Widgets/widgets.css`。地图容器必须有实际宽高。

本仓库 Vite 示例使用插件自动复制资源，设置 `/cesium/`；部署到子路径时需同时调整 Vite base 和资源基础路径。工具库自身不复制资源、不设置 Token、不修改 Viewer 原型或全局 Cesium 配置。

## 创建、使用与清理

```ts
import { GridImageryProvider } from 'cesium'
import { createMap, LayerKit, MaskKit, CoordinateKit } from 'terra-map-kit'
import 'cesium/Build/Cesium/Widgets/widgets.css'

const viewer = createMap('map', {
  baseLayerPicker: false, baseLayer: false, geocoder: false
})
const layers = new LayerKit(viewer)
const masks = new MaskKit(viewer)
await layers.addImageLayer({ id: 'grid', provider: new GridImageryProvider({}) })
viewer.camera.setView({ destination: CoordinateKit.fromDegrees(116.39, 39.9, 2000000) })

// 页面/组件卸载时，先 Kit 后 Viewer。
masks.dispose()
layers.dispose()
viewer.destroy()
```

选择在线影像、地形或 3D Tiles 时由应用提供相应 Provider 和所需 Token，不提交凭据。SSR/Node 可以导入模块并调用坐标方法；创建 Viewer 仍需浏览器 DOM/WebGL。

## 限制和升级

MaskKit 是实验性局部地表掩膜，完整几何、范围、更新及异常约定见 [API 说明](./API说明.md)。当前验证使用锁定的 Cesium 1.145.0；其他版本及浏览器/GPU环境需在项目中再次验证。升级包或 Cesium 后应重新验证坐标误差、对象清理、资源路径及掩膜视觉效果。
