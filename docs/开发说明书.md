# TerraMapKit 开发说明书

> 状态：首版与特效扩展（2026-10-02）。Core、Coordinate、Layer、Effect 及 Pick/Draw/Camera/Popup/Measure/Tileset/Track 已实现，Mask 为局部贴地实验性实现；现有模块配套 Node.js 测试和浏览器交互示例。线上发布仍待信息和权限确认。

## 1. 技术选型与目录

- **语言与模块**：TypeScript、ESM。首版用 `tsc` 输出 JavaScript、`.d.ts` 与 Source Map，减少构建层复杂度。
- **引擎依赖**：`cesium` 作为 peer dependency；开发时再安装一份用于类型检查和示例验证。
- **文档**：VitePress，中文首页、说明书和 API 页面。
- **包管理**：pnpm；锁文件提交仓库后，CI 使用冻结安装。
- **发布**：先维持私有骨架；M3 完成后再开放 npm 发布。


## 2. 架构约束

### 2.1 原生 Viewer 是公共边界

`createMap` 和 `MapKit.createMap` 返回 `Cesium.Viewer`。`LayerKit`、`MaskKit` 的构造函数接收 `Viewer`；`CoordinateKit` 的纯计算方法无须 `Viewer`。这样应用可以直接使用 `viewer.imageryLayers`、`viewer.scene` 和 `viewer.camera`，不会出现工具包自定义属性与 Cesium 原生属性混用的歧义。

```ts
// API 已实现；provider 由调用方创建，MaskKit 仍为实验性。
const viewer = createMap('map', viewerOptions)
const layers = new LayerKit(viewer)
const mask = new MaskKit(viewer)

const layer = await layers.addImageLayer({ provider })
viewer.imageryLayers.contains(layer) // 原生 Cesium 操作
```

不得修改 `Viewer.prototype`，不得在 `viewer` 实例上动态挂载工具包属性。模块之间通过 Cesium 类型或小型内部接口协作，避免 `LayerKit` 依赖 `MaskKit` 的内部状态。

### 2.2 模块与导出

- 根入口 `terra-map-kit` 提供常用 API；`terra-map-kit/core`、`/layer`、`/mask`、`/coordinate` 便于按模块导入。
- 公开方法使用正确英文拼写，如 `createMap`，不提供 `creatMap` 等拼写错误别名。
- 内部辅助函数不从根入口导出。类型和错误必须可通过公开入口访问。
- 无导入时副作用，不自动创建地图、不设置 ion Token、不读写全局配置。
- `package.json` 的 `exports` 与 `dist` 文件一一对应；发布前用真实打包文件验证。

### 2.3 对象所有权和清理

- `Viewer` 由调用方持有并负责 `viewer.destroy()`。Kit 的 `dispose()` 不销毁 Viewer。
- `LayerKit` 只管理自己登记的影像图层。若外部代码已经移除某图层，再调用 Kit 清理仍应安全。
- `MaskKit` 只移除自己创建的 Entity/Primitive/Stage 和事件监听器。
- 清理函数可重复调用，不留下 WebGL 对象、事件句柄或定时器。

## 3. 功能实现方案

### 3.1 Core / MapKit：地图初始化

1. 定义 `createMap(container: string | HTMLElement, options?: Viewer.ConstructorOptions): Viewer`。
2. 直接调用 Cesium `new Viewer(container, options)`；仅在必要时添加输入校验，不悄悄修改用户选项。
3. `MapKit.createMap` 与独立 `createMap` 指向同一实现，避免两份逻辑分叉。
4. 文档提供容器尺寸、Widgets CSS、Cesium 静态资源路径及离线底图配置示例。

Cesium 的 Web Worker、Assets、Widgets 等静态目录及 `CESIUM_BASE_URL` 由**使用此包的应用**配置。工具包不把这些大资源打入 npm 包。浏览器环境才调用 Viewer 构造函数；模块导入本身不访问 `window`，以免文档构建或 SSR 环境在导入阶段报错。

本节已在 `src/core/index.ts` 落实：直接构造 Viewer，原样传入容器与选项，两个入口为同一函数。`tests/core.test.mjs` 验证 Node.js 无 DOM 导入、根入口与子路径一致及原生缺失容器异常。真实浏览器创建、选项透传、销毁和重建通过 `examples/basic` 示例验证，不以 Node 单元测试替代 WebGL 验证。

示例使用显式开发依赖 Vite；`examples/basic/vite.config.mjs` 复制 Cesium 四类资源目录并定义 `/cesium/` 基础路径，`main.js` 加载 Widgets 样式与本地生成的网格 Provider。`pnpm example:dev` 启动，`pnpm example:build` 构建，`pnpm example:preview` 预览。根目录 `pnpm check` 包含示例构建，CI 不执行浏览器交互验证。

### 3.2 LayerKit：影像图层

1. 构造时校验 `viewer` 存活状态，在实例内部维护 `Map<string, ImageryLayer>`。
2. `addImageLayer` 接收原生 `ImageryProvider | Promise<ImageryProvider>`；等待异步 Provider 后创建并加入 `viewer.imageryLayers`。
3. ID 由调用方指定或工具包生成；重复 ID 明确报错。`alpha` 限定在 0 至 1，`show` 默认为 true。
4. 返回原生 `ImageryLayer`。方法失败时不得登记半成品图层。
5. `removeImageLayer` 和 `dispose` 仅清理本实例登记的图层；若外部已移除，内部索引也应同步清除。

首版不重新封装 Cesium 的每一种影像 Provider。应用可以先创建 `UrlTemplateImageryProvider`、`WebMapServiceImageryProvider` 或其他 Provider，再交给 `LayerKit`。后续快捷 API 根据实际重复需求添加。

本节已落实于 `src/layer/index.ts`。等待中的 ID 使用 Set 预占；选项在 await 前读取。Provider 完成后复查 Kit/Viewer 状态；同步 layerAdded 回调清理 Kit 时也不会留下图层。Node 测试使用真实 ImageryLayer/ImageryLayerCollection 校验所有权、外部提前移除、重复 ID、异步失败和等待期间清理。

### 3.3 MaskKit：区域外侧掩膜

首版实现为“局部外侧遮暗”：`src/mask/index.ts` 使用 PolygonHierarchy 外侧矩形加单个内洞，以 Entity/PolygonGraphics 贴地渲染，采用 ArcType.RHUMB 和 ClassificationType.TERRAIN。RHUMB 保持纬度边界与局部经纬平面校验一致，不承诺大范围地理拓扑能力。

实现顺序：

1. 校验至少三个不重复的 WGS84 点，检查纬度范围、闭合处理、自交与边界退化。
2. 对区域与外侧边界统一使用经纬高到 Cesium 位置的转换，构造“外环 + 区域洞”的几何。
3. 将创建的 Entity 或 Primitive 放在 Kit 私有集合中；返回带 `remove()` 或 `dispose()` 的句柄。
4. 更新时替换几何并释放旧对象；移除时解除所有资源引用。
5. 在平坦地表、地形、倾斜视角、远距离视角验证遮挡；记录与 3D Tiles、跨日期变更线、极区的限制。

已实现 3–512 顶点校验、闭合点处理、重复点/自交/回折/退化拒绝、外侧矩形严格包含校验；限制纬度 ±80、矩形跨度不超过 120 度，拒绝跨日期变更线。句柄 update 先校验再原位替换 Entity 的 polygon，保留实体与 ID；remove/dispose 仅移除本实例实体。无效更新不会改变旧几何。

本机浏览器验证局部孔洞、颜色与几何更新、清理、椭球与离线合成地形及倾斜视角；不承诺覆盖矩形之外、3D Tiles、天空或独立 Entity。真实在线地形和不同 GPU/浏览器尚未验证，详见 API 页限制；状态保持实验性。

### 3.4 CoordinateKit：坐标转换与生成

- `fromDegrees(lon, lat, height = 0)` 内部调用 `Cartesian3.fromDegrees`，输出原生 `Cartesian3`。
- `fromDegreesArray(points)` 逐点转换；输入使用命名字段 `{ longitude, latitude, height? }[]`，避免数组下标含义不明。
- `toDegrees(cartesian)` 通过 `Cartographic.fromCartesian` 与角度转换返回 `{ longitude, latitude, height }`。
- 已实现：校验有限数值、经度 `[-180, 180]` 和纬度 `[-90, 90]`；使用显式 `Ellipsoid.WGS84`，不做无提示的坐标系转换。导出 `DegreesPoint` 与 `DegreesCoordinate` 类型，批量接口接受只读数组。
- 明确浮点误差：往返转换用容差比较，不保证字符串或二进制位完全一致。

实现位于 `src/coordinate/index.ts`；`tests/coordinate.test.mjs` 使用 Node.js 内置测试运行器，从构建后的根入口和子路径加载包。覆盖 WGS84 已知点、往返误差、极点、经纬度边界、非法输入、批量顺序和地心异常。`pnpm test` 先构建后执行测试，`pnpm check` 将其纳入 CI 检查。

## 4. 类型、错误与测试约定

### EffectKit 扩展

`src/effect/index.ts` 使用 Entity、CallbackProperty 和 ColorMaterialProperty 实现波纹、扩散与波形线；动画时间来自 Viewer.clock.currentTime，pause/resume 保存并恢复相位。每个 Kit 仅在运行效果存在时订阅一个 onTick，主动 requestRender，dispose 解除监听并只移除自有 Entity。更新完整参数后替换实体并重启周期，输入校验失败保留旧对象。范围、采样与高度限制见特效说明页。

- 公共函数显式标注输入、输出类型；直接暴露 Cesium 类型时不复制其结构。
- 参数错误使用 `TypeError` 或 `RangeError`；资源已销毁时使用清晰的状态错误。异步 Provider 失败保留原始错误原因。
- 单元验证覆盖坐标边界、图层登记和清理、重复 ID、异常路径。
- Cesium 渲染依赖 WebGL，掩膜必须在浏览器场景中验证。只通过几何单元测试不足以确认视觉结果。
- 每次 M1/M2 实现后运行类型检查、构建、文档构建与示例手动验证；测试范围针对实际风险扩展。

## 5. 文档与示例规范

每个 API 页面至少说明用途、签名、参数单位、返回值、错误、生命周期和一段可运行示例。状态分为“计划中 / 已实现 / 实验性”。代码功能完成后再把对应页面改成“已实现”。

应用示例必须说明：

1. 安装 `cesium` 和 TerraMapKit。
2. 导入 `cesium/Build/Cesium/Widgets/widgets.css`。
3. 复制并托管 Cesium 所需的 Workers、ThirdParty、Assets、Widgets 静态资源，设置 `CESIUM_BASE_URL`。
4. 为使用 Cesium ion 的资源提供应用自己的 Token；不将 Token 提交到仓库。
5. 组件或页面卸载时清理 Kit，并由应用销毁 Viewer。

文档站当前是静态说明站，不嵌入 Cesium 场景，因此 VitePress 构建不依赖浏览器 WebGL。

## 6. GitHub Pages 和 npm 发布路径

### GitHub Pages

仓库绑定后，工作流在 `main` 分支推送时安装依赖、构建 VitePress、部署 `docs/.vitepress/dist`。项目站点通常位于 `/<仓库名>/` 子路径，因此工作流在构建时设置 `DOCS_BASE`；本地开发默认 `/`。如使用自定义域名，再调整 `base` 配置。

仓库管理员需在 GitHub Pages 设置中将构建来源设为 **GitHub Actions**。本地已配置 GitHub origin，但本轮未推送、核验远程运行记录或启用 Pages，不能据此声称在线部署成功。

### npm

首次发布前完成以下事项：

1. 确认 `terra-map-kit` 名称可用；若不可用，改为 `@账号/terra-map-kit` 并同步示例。
2. 确定许可证、仓库 URL、主页、版本策略和受支持的 Cesium 版本范围。
3. 完成 M1/M2 功能和文档，解除 `private: true`，设置正式版本。
4. 运行 `pnpm check`，用 `npm pack --dry-run` 查看实际包内容，并在独立示例项目中安装本地打包文件。
5. 配置 npm 账号和发布权限，执行首次发布；若使用作用域公开包，按 npm 规则使用 `--access public`。

不在源码或 GitHub 工作流中存放 npm 凭据。是否增加自动发布工作流，等账号与仓库确定后再设计。

## 7. 开发顺序

1. **M0**：完成本骨架与两份说明书，确认模块和 API 方向。
2. **M1**：实现 Core、Layer、Coordinate；补充实际可运行示例与测试。
3. **M2**：对 Mask 做浏览器原型与效果验证，再实现稳定 API。
4. **M3**：检查文档、包名、许可证和实际安装效果，绑定仓库并发布站点与 npm 包。
