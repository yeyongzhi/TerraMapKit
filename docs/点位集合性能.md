# 点位集合性能

PrimitiveMarkerKit 是 marker 入口中的通用集合封装，支持原生点和图标、批量更新、距离显示控制与身份拾取。[API 与限制](./kits/MarkerKit.md)。

## 运行与统计

打开[示例中心](./示例中心.md)的“Primitive 点位与性能”，选择 1000、10000 或 50000，运行 Entity / Primitive 对比。三种模式均在相同 Viewer、相机和输入坐标下创建、更新、移除，最后销毁 Kit。Entity 批次按 10000 分块，Primitive 采用同样分块方式；都是批量操作，不代表逐点 API 性能。

add、patch、remove 为同步 JavaScript 调用耗时，不含输入数组生成。frameWait 为创建调用完成到后续渲染事件的墙钟等待；图标模式还等待所有 Billboard.ready。这不是 GPU 执行时间或稳定帧率。点模式尺寸 5→6，Entity 关闭描边；图标模式使用共享本地纹理 5→6，成本与原生点不同。

先创建并清理一个 Entity 点以预热 Cesium 延迟创建的可视化集合。原生可视化集合会保留到 Viewer 销毁；资源残留相对于预热后的基线统计。每种模式检查 Entity 数、scene.primitives 集合数，以及 onTick、postRender、collectionChanged 监听数；不等于堆或显存泄漏分析。

## 2026-10-04 本机采样

Windows，Headless Chrome 153，SwiftShader 软件渲染，画布 908×715，requestRenderMode=true。每个数量每种模式采样一次，单位毫秒；仅说明本机这次表现，不是生产性能保证。九组全部无新增 Entity、集合或上述监听残留。

普通标记需要文字、编辑、序列化时使用 MarkerKit；大量简单点或共享图标可选 PrimitiveMarkerKit，结合实际数据、设备和更新频率复测。
