# 标记性能基准

示例中心的“标记批量性能基准”支持 100、1000、5000 个点标记，比较逐个与批量创建、更新点颜色及尺寸、移除。每种方式执行三轮，输出同步耗时、collectionChanged 通知次数、同步 requestRender 次数及实体残留。JSON 可直接复制。

正常批次只发出一次集合通知与一次 Kit 请求；真实 Viewer 还可能发出 Cesium 自身的渲染请求，因此示例记录的请求数包含原生调用。耗时仅包含同步 API 工作，不包含之后的几何构建、瓦片加载或 GPU 上传，也不代表 FPS 或 GPU 内存。

```bash
pnpm test:browser --grep "marker benchmark performance"
```

浏览器测试使用 Chromium/SwiftShader，按三种数量各采样六组，并验证通知次数与实体清理。输出保存于 artifacts/performance/markers-browser.json。该文件是本地测量产物，不作为固定性能承诺；目标设备应重新测量。单独记录创建、更新和移除，避免把通知减少误写成每项耗时都更快。

## 本次采样

2026-10-04，Windows Chromium 153 / SwiftShader，画布 908×715，启用按需渲染。下表为各操作三轮中位数，单位 ms；每个数值来自独立的逐个或批量路径。

| 数量 | 逐个创建 | 批量创建 | 逐个更新 | 批量更新 | 逐个移除 | 批量移除 |
| --- | --- | --- | --- | --- | --- | --- |
| 100 | 4.3 | 2.3 | 3.7 | 2.7 | 0.9 | 0.2 |
| 1000 | 24.8 | 19.4 | 38.9 | 28.8 | 15.6 | 1.3 |
| 5000 | 288.7 | 86.8 | 363.2 | 86.0 | 212.7 | 47.4 |

18 组采样均未留下实体，也未增加 collectionChanged、onTick、postRender 监听。三种操作的通知与同步渲染请求均从逐个路径的 N 次降为批量路径的 1 次。未测量 GPU 内存、持有旧句柄时的堆内存或运行中 FPS。

按需渲染测试另行覆盖标记、绘制、异步影像及特效暂停恢复。特效暂停时将动画回调标记为常量，并在 seek、patch、恢复或播放完成时通知属性变化；移除后释放时钟订阅。加载地形或异步几何期间仍可能发生原生刷新。
