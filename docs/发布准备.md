# 首版发布准备

当前代码可用于本地验证，`private: true` 与 `0.0.0` 仍保留，尚未执行 npm 发布或 GitHub Pages 部署。

## 本地验证

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm package:check
```

`check` 包含源码类型检查、Node.js 测试、工具库构建、文档和浏览器示例构建，并执行真实 npm 包清单校验。`package:check` 可单独构建库并校验六组导出文件，拒绝意外文件和内嵌依赖，生成本地 tgz。库产物不含 Cesium 引擎静态资源、文档、示例、测试和本地配置；Cesium 为 peer dependency。

独立消费项目可用 `pnpm add cesium /绝对路径/terra-map-kit-0.0.0.tgz` 安装，再检查根入口与 core/layer/mask/coordinate/effect 子路径。浏览器项目仍需自行配置静态资源与 Widgets CSS。

注意：新安装 Cesium 1.145.0 曾因浮动 engine/widgets 子依赖不匹配而失败。独立验证采用[安装指南](./安装与使用.md)中的匹配版本；公开发布前还应确定消费应用的兼容策略，不能仅依赖本仓库锁文件。

## 尚待用户确定的发布信息

- npm 账号/组织与包名。`terra-map-kit` 为当前候选，不代表已核实可注册或有发布权限。
- 许可证及版权主体；当前没有擅自授予开源许可证。
- 正式版本与 MaskKit 实验性状态是否符合本次公开发布预期。

本地已配置 GitHub `origin`，当前分支为 `main`。Pages 工作流已存在，但远程运行结果、Pages 设置和在线地址尚未核验；应在仓库设置中选择 GitHub Actions，并确认 `DOCS_BASE` 对应仓库子路径。文档站不包含地图示例；示例是独立根路径静态应用。

## 信息确定后的发布步骤

1. 写入正式包名、版本、许可证、仓库和主页等元信息，补充 LICENSE。
2. 更新文档示例中的包名，确认 Cesium 支持版本；重新执行上述检查及 tgz 安装验证。
3. 解除 `private: true`，在具备发布权限的账号下发布。作用域公开包按需使用 `npm publish --access public`；非作用域包使用 `npm publish`。
4. 提交并推送经审查的代码，查看 CI；启用并验证 Pages 部署后再写入实际站点地址。

上述为后续操作说明，不代表本次已执行。Marker/Label/Draw/Effect/Analysis 等仍为首版之外的后续功能池，不包含在当前交付中。
