# TerraMapKit 项目说明书

> 状态：首版实现与本地验证（2026-10-02）。Core / MapKit、CoordinateKit、LayerKit 已实现；MaskKit 为实验性局部贴地掩膜，已配套交互示例与测试。发布条件见[发布准备](./发布准备.md)。

## 1. 项目定位

TerraMapKit 是面向 CesiumJS 的通用 TypeScript 地图工具包，为重复出现的地图操作提供稳定、可组合的 API。使用者始终能够取得并直接使用原生 `Cesium.Viewer`。工具包不绑定 Vue、React 等应用框架，也不替代 CesiumJS 本身。

项目最终以 npm 包分发，以 VitePress 提供使用指南、API 说明和示例；文档站部署到 GitHub Pages。GitHub 仓库地址与 npm 发布账号稍后绑定。

### 目标用户

- 在 Web 应用中使用 CesiumJS、需要复用地图能力的开发者。
- 希望保留 Cesium 原生对象与类型，同时减少常见业务封装重复代码的团队。

### 设计原则

1. **原生对象优先**：`createMap` 返回 `Cesium.Viewer`，图层方法返回原生 `Cesium.ImageryLayer`。
2. **模块独立**：地图、图层、掩膜、坐标等功能按 Kit 分组；使用者只引入需要的模块。
3. **行为可预期**：不修改 `Viewer` 原型或动态增加 `.layers` 等属性，不清理应用自己创建的对象。
4. **分阶段交付**：先完成首版的五类功能，绘制、标注、特效等在后续版本逐步加入。
5. **文档与代码同步**：每个已实现的公开 API 配套参数、返回值、示例、异常和资源清理说明。

## 2. 首版功能范围

| 模块 | 必做能力 | 交付标准 |
| --- | --- | --- |
| Core / MapKit | 根据容器和 Cesium Viewer 选项创建地图；返回原生 Viewer | 可直接调用 `viewer.scene`、`viewer.imageryLayers` 等原生 API；地图销毁责任清晰 |
| LayerKit | 添加、查询、移除影像图层；支持可见性和透明度；接受 Cesium 原生影像 Provider | 返回原生 `ImageryLayer`；能够与原生图层混用；不误删非本 Kit 创建的图层 |
| MaskKit | 以一个多边形为关注区域，对外侧区域施加半透明遮罩；可更新或移除 | 掩膜内外视觉关系正确；重复创建、更新、移除后无残留；限制条件在文档中明确 |
| CoordinateKit | 经纬度和高度生成 `Cartesian3`；批量生成；`Cartesian3` 转回经纬高 | 参数单位明确；常规点、边界值和往返转换通过验证 |
| 文档与工程 | VitePress 站点、API 文档、构建和发布准备 | 本地可构建；GitHub Pages 工作流可在绑定仓库后启用；发布包内容可检查 |

### 2.1 地图初始化

- 提供 `createMap(container, options?)` 与 `MapKit.createMap(container, options?)` 两种入口，使用同一套实现。
- 将可传入的 Cesium Viewer 构造选项尽量保持原样；工具包不暗中覆盖用户设置。
- 不内置 Cesium ion Token，也不强制某一种在线底图。
- 文档明确说明 Cesium Widgets 样式和静态资源由应用配置。

### 2.2 影像图层

- `LayerKit` 通过构造函数接收一个原生 `Viewer`。
- 首版接受现成的 `ImageryProvider` 或异步 Provider，并在 `viewer.imageryLayers` 中添加图层。
- 支持可选 ID、透明度、显隐和按 ID/原生图层对象移除。
- 明确“Kit 管理的图层”与应用直接添加的原生图层之间的所有权边界。
- WMS、WMTS、URL 模板等来源先可通过 Cesium 原生 Provider 接入；专门的快捷构造方法可后续增加。

### 2.3 区域掩膜

- 输入单个简单区域的 WGS84 经纬度点序列，区域内部保持可见，在外侧矩形范围内覆盖可配置颜色与透明度；矩形以外不遮罩。采用外环加孔洞的贴地多边形，不是全球或屏幕遮罩。
- 掩膜支持创建、更新、移除，多个掩膜实例之间不应互相破坏。
- 首版优先支持常规局部区域；跨日期变更线、极区、复杂自交多边形、多孔洞及 3D Tiles 遮罩能力在实现验证前不作承诺。
- 文档须明确掩膜作用的地表/对象范围、可见视角限制，以及性能边界。

### 2.4 坐标转换与生成

- `CoordinateKit.fromDegrees(longitude, latitude, height?)` 生成 `Cesium.Cartesian3`。
- `CoordinateKit.fromDegreesArray(points)` 批量生成 `Cesium.Cartesian3[]`。
- `CoordinateKit.toDegrees(cartesian)` 返回经度、纬度和高度，便于往返使用。
- 经纬度按 WGS84、角度制，高度按米；非法数值和纬度越界需给出明确错误。
- 首版不包含鼠标拾取、随机点生成、GCJ-02/BD-09 转换。

## 3. 后续功能池

以下顺序可根据实际项目使用反馈调整，不代表首版已实现。

| 阶段 | 模块 | 候选能力 |
| --- | --- | --- |
| 第二阶段 | MarkerKit / LabelKit | 点位、图片标注、HTML 标注、聚合、闪烁图标、交互事件 |
| 基础已实现 / 待扩展 | DrawKit | 点线面绘制、撤销、清理、GeoJSON 导出已实现；编辑手柄待扩展 |
| 已开始实现 / 后续扩展 | EffectKit | 已实现 Entity 波纹圈、扩散圈、波形线与生命周期；发光线/扫描等仍可后续扩展 |
| 第三阶段 | LayerKit 扩展 | WMS/WMTS/URL 模板快捷创建，3D Tiles、地形图层管理 |
| 基础已实现 / 待评估 | MeasureKit / AnalysisKit | MeasureKit 距离、局部面积和高差已实现；高级分析待评估 |

未来功能须分别评估 Cesium 版本兼容性、渲染性能、WebGL 资源占用和移动端表现，避免把演示效果直接当成通用 API。

## 5. 非功能要求

- **兼容性**：使用 TypeScript 声明；CesiumJS 为 peer dependency，避免应用打入重复引擎。
- **体积**：公共入口和模块子路径导出；不在包内复制 Cesium 静态资源。
- **稳定性**：管理类具备明确的 `dispose()` 语义，重复清理应安全。
- **质量**：重要逻辑使用单元测试，依赖浏览器渲染的掩膜使用实际场景验证。
- **文档**：面向开发者的中文文档，包含安装、资源配置、示例、API、限制和升级说明。

## 6. 当前边界与待确认事项

- 当前已实现首版及 Kit 模块，MaskKit 为实验性且受局部范围限制；`package.json` 设为 `private: true`，防止发布条件不全时提前发布。
- `terra-map-kit` 是候选 npm 包名；发布前需在 npm 账号下核对名称或改为作用域包。
- 本地 Git 已配置 GitHub origin，当前分支为 main；远程默认分支和 Pages 设置/地址尚未核验。npm 账号/组织及许可证仍待确定。
- 后续实现中若需更改首版范围或公开 API，先更新本文件和 API 说明，再修改代码。

PickKit、CameraKit、PopupKit、TilesetKit、TrackKit 基础能力已实现；3D Tiles 由 TilesetKit 独立管理，轨迹时钟及弹窗 DOM 单独清理。详见 [Kit API](./API说明.md)。
